# Known issues (A16 build, on device)

## 1. Brightness flash when locking with fingerprint enabled (reported 2026-11-16)
- Symptom: on locking the screen (screen-off), brightness shoots very high for a fraction of a second. Disabling fingerprint unlock removes it; lockscreen then fades smoothly. Sensor is an optical under-display (UDFPS), not ultrasonic.
- Suspected cause (unverified): the optical FOD path forces high-brightness-mode (HBM) / a dim layer at the display driver. In-tree pieces: `hardware/oplus/fingerprint/UdfpsExtension.cpp` (SurfaceFlinger UDFPS z-orders 0x41000005 dim layer, 0x41000033 pressed layer) and `/sys/kernel/oplus_display/{hbm,notify_fppress,dimlayer_bl_en,power_status}` (init.oplus.rc). Likely the pressed/dim layer or HBM is still asserted during the screen-off transition.
- To diagnose, while reproducing (adb root):
  - `adb shell "while true; do echo $(date +%T.%N) hbm=$(cat /sys/kernel/oplus_display/hbm) fp=$(cat /sys/kernel/oplus_display/notify_fppress) dim=$(cat /sys/kernel/oplus_display/dimlayer_bl_en) pwr=$(cat /sys/kernel/oplus_display/power_status); done"` (lock the screen during it)
  - `adb logcat -b all -v threadtime | grep -iE "udfps|fod|fingerprint|hbm|dimlayer|SurfaceFlinger|DisplayPower"`
- **Diagnosis (hbm.log, 2026-11-16 22:45:12):** NOT the `hbm` node (stayed 0). `notify_fppress` is write-only (read gives I/O error). At the moment of "Going to sleep" (22:45:12.273) SystemUI starts a fingerprint auth client and `UdfpsController: showUdfpsOverlay reason=4`; 17 ms later the kernel logs `oplus_display_set_dimlayer_hbm set oplus_dimlayer_hbm = 1`. The panel is still on at auto brightness (74%) and only powers off at 22:45:12.774 (`oplus_display_set_power_status = 0`), so for ~0.5 s the FOD dim-layer HBM is asserted over a lit screen = the brightness flash. `dimlayer_hbm` is reset only on the next unlock/overlay hide (22:45:17.273).
- Cause: UDFPS overlay (and its HBM dim layer) is shown while going to sleep. Related config: `config_screen_off_udfps_enabled=true` (sm8250-common overlay; default-off setting `SCREEN_OFF_UNLOCK_UDFPS_ENABLED`), logic in `frameworks/base/.../biometrics/UdfpsController.java`.
- Test: disable the screen-off fingerprint unlock setting; if the flash disappears this confirms it. Candidate fix: don't show the UDFPS overlay/dim layer (or don't assert HBM) when transitioning to DOZING/screen-off — change in SystemUI/UdfpsController or the display HAL dim-layer handling. Not yet implemented.
- **Fix implemented (2026-11-16, UNTESTED, not yet built/flashed):** `frameworks/base/packages/SystemUI/.../biometrics/UdfpsController.java` (A16 tree). Tracks `mGoingToSleep` (set in `WakefulnessLifecycle.onStartedGoingToSleep`, cleared on `onStartedWakingUp`/`onScreenTurnedOn`). `showUdfpsOverlay()` for `REASON_AUTH_KEYGUARD` while `mGoingToSleep && mScreenOn` stores the overlay in `mPendingSleepOverlay` and returns; it is shown from `onScreenTurnedOff()` (panel already off, so the HBM dim layer is invisible) or `onScreenTurnedOn()` (sleep aborted). `hideUdfpsOverlay()` clears the pending overlay. Patch copy: `scripts/patches/frameworks-base-udfps-defer-overlay-on-sleep.patch` (apply in frameworks/base to rebuild from scratch/A17).
- Chain, for reference: SystemUI UDFPS overlay layer -> SurfaceFlinger (`OutputLayer.cpp` maps layer names to z-orders via `UdfpsExtension.cpp`: dim layer 0x41000005, touched layer 0x41000033) -> HWC/SDM (`hwc_layers.cpp`, `hw_device_drm.cpp`, FOD_PRESSED_LAYER_ZORDER) -> kernel `oplus_display_set_dimlayer_hbm`.
- Risks of the fix: screen-off fingerprint unlock / AOD finger-down could be delayed by up to the sleep transition (~0.5 s); if the overlay never appears after screen-off, revert the patch. If the flash persists, the trigger is elsewhere (e.g. HAL) and needs another log.
- Status: fix pending build+test; same fix not yet applied to A17.
